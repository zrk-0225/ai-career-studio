# AI 领航 · 人工智能专业职业生涯规划学习实践工作台

> **项目说明**——这个作品是什么、怎么打开、怎么用。
> 实现思路、代码拆解和测试记录另见《AI领航_讲解》文档。

一个面向人工智能专业本科生的职业规划工具：做完 38 道测评题，系统会算出你和七个 AI 就业方向各自的匹配程度，给出能力差距分析、四年行动路线和一份可以直接提交的职业规划书。

**特别之处一：给的是「档位」，不是「第几名」。**
七个方向里有五个的岗位画像高度重叠，实测第 1 名和第 2 名的分差中位数只有 1~2 分，同一个人重答一遍有 **30%~40%** 的概率换人。所以本工具**不展示名次和小数分**，只把分差在 5 分以内的方向归为同一档，并说明档内不分先后。详见讲解文档 5.13 节。

**特别之处二：匹配算法的权重会跟着年级变。**
大一学生能力还没成形，用固定权重会得出"你什么都不适合"的错误结论。所以大一时主要看兴趣和性格，越接近毕业能力权重越高。

**特别之处三：不声称自己"准"。**
模拟同一个人重答一遍，第 1 名有 **30%~40%** 的概率会变——所以本工具不给名次，只给档位（档位成员的重叠度比名次稳得多：重答后第 1 档成员基本不变，少数情况在边界上换一个）。**它是一个结构化的自我反思工具，不是测量仪器**——能帮你排除明显不合适的、看清自己的短板，就已经达到目的。

**特别之处四：兴趣画像用的是真实数据。**
七个方向的霍兰德六型兴趣画像，取自**美国劳工部 O*NET 数据库**（Creative Commons 许可）的实测得分，不是我编的。能力要求、薪资、学历则是我参考公开报告和行业情况估计的——哪些是真的、哪些是估计的，下面「数据来源与方法」一节列了完整的表。

**特别之处五：我估计错了会怎样，测过。**
能力要求那 56 个数值是我估的，没有数据依据。所以我做了敏感性测试：如果是**无规律乱填**，偏差 ±3 分结果就崩；但真实误差是有规律的（整体偏高 / 某维度系统性偏 / 某方向整体偏），合理误差模型下**影响比用户自己的答题抖动还小（0.96 对 0.93）**。结论是：**这个算法依赖数值之间的相对关系，不依赖绝对数值。** 详见下面「数据来源与方法」第三节。

> **这个作品是怎么想出来、怎么写出来的**（需求理解、技术选型、算法推导、代码拆解、测试记录），
> 见随附的《AI领航_讲解》文档——在源码仓库里是 `docs/AI领航_讲解.md`，完整版压缩包里是同一层的 `AI领航_讲解.docx`。

## 快速开始

三种方式，按你的情况挑一种。

**方式一：直接打开网址（最快，什么都不用装）**

作品已经发布在 GitHub Pages 上，电脑和手机都能直接打开：

```
https://zrk-0225.github.io/ai-career-studio/
```

> 服务器在国外，**国内访问有时不稳定**。打不开就多刷几次，或者改用下面的本地方式。
>
> 线上那份和本机那份**数据是分开的**（浏览器的 localStorage 按域名隔离）。
> 你在线上做的测评不会同步到本机，反过来也一样。

**方式二：双击 `index.html`（离线可用）**

把源码下载下来，双击 `index.html`，浏览器就会打开工作台。不需要安装任何东西，不需要联网，不需要命令行。数据存在你自己电脑的浏览器里。

**方式三：本地起个服务（要接大模型、或想在手机上访问时用）**

```bash
# 在项目根目录执行，任选一种
python -m http.server 8000
npx serve .
```

然后浏览器打开 `http://localhost:8000`。

## 怎么用

**第一次打开会先走一遍三屏向导**：介绍这是什么 → 说明你的数据只在本地 → 让你填年级（必填）。

> 年级不是可有可无的标签，它会改变匹配算法的权重。所以这里做成了必填，而不是给个默认值蒙混过去。

之后按这个顺序用：

1. **做测评** —— 左边「自我认知」，38 道题，大约 12 分钟。能力自评题有具体评分标准，题目的问法会跟着年级变
2. **看诊断** —— 「匹配诊断」算出七个方向的排名，点任意一个看雷达图和差距明细
3. **做对比** —— 在两个方向之间犹豫时，用「方向对比」把它们的岗位要求叠在一起看
4. **定目标** —— 在方向详情里点「设为目标方向」
5. **排计划** —— 「四年规划」在通用任务之上，会**按你的目标方向生成专项任务、按你的能力短板补上该补的**（带「方向专项」「补齐短板」标签），并且**按毕业去向分岔**：瞄准算法工程师这类需要读研的方向，大四的任务会变成推免/考研而不是秋招。路线可以手动改，也可以让它按目标方向自动判断
6. **看成长** —— 每隔一段时间重测一次，「成长曲线」会画出能力变化轨迹
7. **问助手** —— 「AI 助手」解答方向选择、学习路线、实习准备等问题，它能感知你正在看哪一页
8. **出文档** —— 「我的规划书」一键导出 Word / Markdown，或打印成 PDF

**备份和清空数据**在右上角的「设置」里。想换电脑就把数据导出成 `.json`，在新设备上导入即可。

**不知道从哪开始？** 点左边或顶栏的「使用指引」，它会按你的年级告诉你现在最该看哪几页。

## 技术说明

- **纯前端，零依赖**。没有用任何第三方库，不需要 npm install，不需要构建步骤
- **不用 ES Module**。所有脚本用经典 `<script>` 标签加载，挂到全局 `AICS` 命名空间上。
  这是为了让 `file://` 协议下双击打开也能正常工作——用 `type="module"` 会被浏览器的跨域策略拦住
- **图表全部手绘**。雷达图、折线图、环形进度、条形图都用原生 Canvas 2D 实现，
  因此完全离线可用，也不会有 CDN 挂掉的风险
- **导出 Word 也是自己实现的**。用带 Office 命名空间的 HTML 存成 `.doc`，Word 和 WPS 都能正常打开，
  同样不需要任何第三方库
- **数据存在浏览器本地**。所有内容保存在 `localStorage`，不上传任何服务器

### 匹配算法

```
能力匹配度 = 100 − Σ(岗位要求权重 × 能力缺口) / Σ(岗位要求权重)
兴趣匹配度 = 余弦相似度(我的兴趣六维向量, 岗位兴趣画像) × 100
偏好匹配度 = 平均(1 − |我的偏好轴 − 岗位偏好轴|) × 100

总分 = 能力 × W₁ + 兴趣 × W₂ + 偏好 × W₃
```

**权重按年级自动调整：**

| 年级 | 能力 | 兴趣 | 偏好 |
| --- | --- | --- | --- |
| 大一 | 15% | 50% | 35% |
| 大二 | 35% | 40% | 25% |
| 大三 | 55% | 28% | 17% |
| 大四 | 70% | 20% | 10% |

（只有四个本科年级。「读研」不是一个年级，而是「四年规划」里的**毕业去向**选项之一——见下。）

## 数据来源与方法

这个作品里的数据分两类：**有公开出处的**和**我估计的**。分开列清楚，是因为它们可靠程度不一样——不说明的话，读者会默认它们一样可靠。

### 一、有出处的数据

| 数据 | 来源 |
| --- | --- |
| 七个方向的**兴趣画像**（霍兰德六型，0~1） | 美国劳工部 **O*NET 数据库** `Interests.txt`，Creative Commons 许可 |
| 学历门槛、薪资区间的**参考值** | 《2024 中国人工智能岗位招聘研究报告》；脉脉校招统计 |

**O*NET 的数据是怎么用的**

O*NET 是美国劳工部的职业信息数据库，免费公开，其中 `Interests.txt` 直接给出每个职业的霍兰德六型**实测得分**（1~7 分制）：

```
https://www.onetcenter.org/dl_files/database/db_30_0_text/Interests.txt
```

七个方向到 O*NET 职业（SOC 码）的映射：

| 本作品的方向 | O*NET 职业（SOC 码） |
| --- | --- |
| 算法工程师 | 15-1221.00 与 15-1252.00 的**均值** |
| 大模型应用开发工程师 | 15-1252.00 Software Developers |
| 数据分析师 / 数据科学家 | 15-2051.00 Data Scientists |
| AI 产品经理 | 15-1299.09 IT Project Managers |
| 嵌入式 / 边缘 AI 工程师 | 17-2061.00 Computer Hardware Engineers |
| AI 平台 / MLOps 工程师 | 15-1299.08 Computer Systems Engineers/Architects |
| 科研 / 学术 | 15-1221.00 Computer and Information Research Scientists |

> 这一步映射是我做的判断，**存在误差**。算法工程师取均值，是因为 O*NET 里"算法工程师"和"科研 / 学术"是**同一个职业**（都是 15-1221.00）——美国的职业分类里，工业界算法岗和学术界研究岗本来就没分开。为了在作品里区分它们，才取了"研究岗 + 开发岗"的均值。

### 二、我估计的数据

| 数据 | 性质 |
| --- | --- |
| **能力要求**（7 个方向 × 8 个维度 = 56 个数值） | ⚠️ 估计 |
| **工作偏好**（三个轴） | ⚠️ 估计 |
| **需求热度**（5 分制） | ⚠️ 估计 |
| 薪资区间、学历建议、公司举例 | 🟡 参考公开报告 + 行业认知 |

薪资和学历**找到了公开报告，但粒度对不上**：报告只到"行业级"（全体 AI 岗位的平均年薪、学历分布），给不到"这七个方向各自"——因为"大模型应用开发工程师"根本不是官方职业分类，没有对应的统计数据。所以这两项也只能估。

> 界面上也标注了这一点：「方向图谱」页顶部写明哪些是估计值，「需求热度」的悬停提示是"估算值，非官方统计"。
> 这些数字的用途是**比较方向之间的相对差异**，不是当绝对数值用。

### 三、估计错了会怎样（敏感性测试）

我没有停在"我参考了行业情况"这句话上——那句话没有信息量。而是直接把估计值人为改错，看结果变多少。

**第一轮，用了一个不现实的误差模型**：把 56 个数值**每格独立随机**扰动。

| 扰动强度 | 排名相关性 | 第 1 档完全一致 |
| --- | --- | --- |
| 0（原始） | 1.00 | 100% |
| ±3 分 | **0.46** | 40% |

±3 分就崩了。但这个模型是错的——它等于假设我完全没有判断力、纯粹在乱填。

**第二轮，换成合理的误差模型**：人估错东西是有规律的，要么整体偏高/偏低，要么某一项系统性估偏，要么某个方向整个估错。

| 误差模型 | 排名相关性 | 第 1 档重叠度 |
| --- | --- | --- |
| 整体偏移 ±10 分（所有方向同时高估或低估） | 0.96 | **100%** |
| 单个维度错 ±15 分（比如"数学"整体估偏） | 1.00 | **100%** |
| 单个方向错 ±15 分（比如算法岗整个画像估偏） | 0.96 | **100%** |
| **【对照】用户自己的答题抖动** | **0.93** | 100% |

**在合理的误差模型下，我的估计即使整体错 10~15 分，影响也比用户自己重答一遍的抖动更小。**

一句话概括：**这个算法不依赖我的数值精确，但依赖数值之间保持一致的相对关系。**

- 我能辩护的："算法岗比产品岗更需要数学"——这是行业常识
- 我辩护不了的："算法岗的数学要求正好是 88 分"——这个数字没有依据
- 而实测说明：**只要相对关系对，绝对值差 10~15 分不影响结论**

> ⚠️ 这个结论**有前提**：只在合理误差模型下成立。第一轮那个崩掉的结果也说明，如果数值之间毫无内在逻辑（真的在乱填），结果就是随机的。所以"有依据"的最低标准是——**数值之间要有一致的逻辑**，而不是每个数字都准。

### 四、算法里用到的统计方法

| 环节 | 方法 |
| --- | --- |
| 能力匹配度 | 逐维度算「岗位要求 − 我的自评」，**只计未达标的部分**，再按该岗位对各能力的看重程度加权平均，用 100 减掉 |
| 兴趣匹配度 | 我的兴趣六型向量与方向画像的**余弦相似度**——衡量的是"形状"像不像，不受打分整体偏高偏低影响 |
| 偏好匹配度 | 工作方式三个轴分别算贴近度，取平均 |
| 三项合成 | 加权平均，**权重随年级变化**（大一能力 15% / 兴趣 50%；大四能力 70%） |
| **分档，而不是排名** | 分差在档宽以内的方向归为同一档、不分先后。默认档宽 5 分，答题一致性偏低时自动放宽到 6~9 分（分不开就是分不开，硬给窄档位等于制造不存在的区分度） |
| 答题一致性检测 | 偏好部分三个轴各设**一正一反两道题**，比较两侧得分是否矛盾 |
| 分数分不开时 | **成对比较**：4 轮二选一，按胜场数排序、用 Elo 分破平；仍然分不出高下就如实说分不出来 |
| 信度测试 | **蒙特卡洛**：生成大量模拟画像，每份模拟"同一个人重答一遍"，统计排名相关性、第 1 名翻转率和第 1 档成员的 Jaccard 重叠度。模型见下 |
| 敏感性测试 | 见上一节 |

**为什么只给档位、不给名次**：信度测试显示，同一个人重答一遍，第 1 名有 **30%~40%** 的概率会换；而第 1 档成员的 Jaccard 重叠度中位是 **0.73~0.83**——也就是重答后第 1 档里通常只有一个成员会变。名次基本在乱跳，档位只在边界上动，所以只报档位。

**信度模拟用的是什么模型**（这一条必须写清楚，否则数字没法复核）：

> 每个模拟学生先抽一个**自洽的**潜在画像——能力八项各自有高有低、兴趣六型各自一个水平、偏好三轴各自一个值；两次作答 = 潜在画像 + 独立噪声（σ=0.5，1~5 量表）；两次作答分别走一遍真正的匹配算法，比较排名和第 1 档成员。用固定随机种子，结果可复现。

| 年级 | 排名相关性 | 第 1 名翻转率 | 第 1 档完全一致 | 第 1 档 Jaccard 中位 |
| --- | --- | --- | --- | --- |
| 大一 | 0.89 | 29.7% | 34.8% | 0.73 |
| 大二 | 0.89 | 30.7% | 32.8% | 0.75 |
| 大三 | 0.86 | 36.9% | 33.9% | 0.80 |
| 大四 | 0.86 | 39.5% | 34.9% | 0.83 |

> ⚠️ **这个数对"重答噪声有多大"很敏感**：噪声取 σ=0.3 时翻转率是 21%~33%，取 σ=0.7 时是 35%~50%。σ=0.5 对应的是一次重测里大约一半的题会变动一档，是个偏保守的取法。所以引用这个数的时候要连着模型一起说。
>
> 这个数字在文档里换过两次，都是因为前两版**来路不正**：最早写的"19%~40%"是早期版本的旧数据（换了 O*NET 兴趣画像之后没跟着改，还被抄进了好几处）；后来改成"17%~25%"，来自一张和另一张表对不上的实验记录，而且没写模拟参数。2026-10-06 用可复现的模型重跑了一遍，就是上面这张表。

### 五、换成真实数据之后发现的一件事

兴趣画像最早是我手编的，后来换成了 O*NET 实测数据。换完把四个年级的信度指标全部重测了一遍。

**结论是"四个年级里三个改善、一个变差"，不是"全面改善"。**

> **大二那一行是唯一的反例，不能省。** 它的"第 1 名翻转率"其实是变好的，但**档位成员的稳定性下降了**——因为大二的权重三项比较均衡（能力 35% / 兴趣 40% / 偏好 25%），换数据后有几个方向正好卡在档位线上，重答一次就容易跨界。
>
> 还有一条教训：我第一次统计时**漏跑了"大二"**，而那恰恰是唯一的反例。虽然是无心之失，但"漏掉唯一不利的数据"和"挑数据"在结果上没区别。补测之后才拿到"3 胜 1 负"这个真实结论。
>
> 逐年级的完整数据表在《AI领航_讲解》5.13 / 5.14 节。

**顺带一个发现**：换成 O*NET 实测数据后，七个方向的兴趣画像两两相似度**反而更高了**。

原因是 O*NET 里所有 AI 相关职业的画像**形状完全一样**——都是研究型（I）和常规型（C）高，其余四项都低，只是幅度有差别：

```
研究科学家    R 3.94  I 7.00  A 2.86  S 2.04  E 2.42  C 4.80
软件开发者    R 3.93  I 5.86  A 2.26  S 1.88  E 1.87  C 5.46
数据科学家    R 2.16  I 6.99  A 2.59  S 1.66  E 1.71  C 5.40
硬件工程师    R 5.79  I 5.64  A 1.84  S 1.79  E 1.88  C 5.28
```

所以**"七个方向太像、排不出稳定的第 1 名"不是我编数据编坏了，是这些职业本身的属性**。这一点之前只是推测，现在用美国劳工部的实测数据坐实了。

### 六、一处需要主动说明的张力

我给的七个方向里有 2 个要求硕士以上（**29%**），而《2024 中国人工智能岗位招聘研究报告》说全体 AI 岗位里要求硕士以上的只占 **9.1%**。

口径不同（我列的 7 个都是专业岗，报告里混了大量标注、运维岗），但**我确实可能整体估高了**。这一点没有解决，如实写在这里。

## 已知不足

- 能力雷达图用的是**自评**数据，不是客观测评（已通过"五档具体评分标准"降低偏差，但仍是自我认知）
- **方向分不开的情况比预想中常见**：用模拟画像实测，第 1 档挤进 6 个以上方向的比例是——大一约 13%、大二约 24%、大三约 38%、大四约 44%。原因是能力自评普遍偏高时各方向的能力匹配度都趋近满分，区分度只剩兴趣和偏好，而兴趣画像彼此相似度本来就有 92%。**这是这个工具最实质的局限**，而且越到高年级越严重（能力权重越高，压缩越厉害）。缓解办法是「匹配诊断」里的**成对比较**：既然分数分不出来，就换成"这两件事你更愿意做哪件"，用你自己的选择补上算法拿不到的那部分信息。但这不叫"解决"——它只是把决定权还给你，而不是替你决定。
- **时间轴依赖"9 月开学"这个假设**：推算"你现在在哪、距离关键节点还有多久"用的是这条通用规律。春季入学、休学过、或者学校学制不同的同学会对不上——界面上把推算结果原样写出来了，也给了改年级的入口，但没有做手动校正位置的功能。
- **规划任务的粒度是统一的**：现在一条任务就是"一个学期要做的一件事"，没有按人调整粗细。真要做细，得让人自己拆——这也是「拆成待办」存在的理由，但工具只提供了入口，拆得好不好还是看用户。
- **四年规划的个性化只做了一半**：大三大四会按你的目标方向和能力短板生成专项任务，但**大一到大二那两栏仍是通用的**——七个方向在那两年要做的事本来就高度重合（数学、编程、机器学习、第一个项目）。要往下做就得按方向重写通用地基，而那会让已经打过勾的进度没法迁移
- **能力要求、工作偏好、需求热度这三项数值是我估计的**，没有用真实招聘数据校验过（界面上已标注为估计值，来源和敏感性测试见上面「数据来源与方法」一节）。薪资和学历找到了公开报告，但报告只到"行业级"，给不到"这七个方向各自"，所以也只能估
- 手机端看板**拖动换列不可用**（HTML5 拖拽不支持触屏），需使用卡片上的箭头按钮
- 导出的 Word 是 HTML 格式的 `.doc`，Word/WPS 能正常打开，但严格说不是 OOXML 格式
- 主流浏览器（Chrome / Edge / Firefox / Safari）都已测试；不支持 IE
